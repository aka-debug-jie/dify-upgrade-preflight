# 路线图阅读与执行

唯一实时状态是根目录 roadmap.yaml；本表解释阶段，不重复维护“已完成百分比”。

| 阶段 | 内容 | 交付目标 | 提示词 |
|---|---|---|---|
| P00 | 事实、支持边与开发环境核验 | 不写业务代码，确认两类以上机器可检测的真实痛点，提出两条可固定的候选升级边及最小环境方案。 | `prompts/P00_discovery.md` |
| P01 | 最小可运行闭环与核心契约 | 先让一个合成快照经过纯规则判定输出正确 JSON 和退出码，再建立可安装的小包。 | `prompts/P01_walking_skeleton.md` |
| P02 | 受限配置采集与脱敏快照 | 把明确指定的 Compose 配置安全转换成声明态快照，而不访问生产服务。 | `prompts/P02_safe_snapshot.md` |
| P03 | 官方基线与三方差异分析 | 正确区分上游变化、本地定制和分歧，避免把自定义配置误判成升级错误。 | `prompts/P03_three_way_diff.md` |
| P04 | 规则目录、证据信任与完整性判定 | 让规则目录和支持边成为有验证边界的数据，而不是加载任意 YAML 后自称安全。 | `prompts/P04_catalog_engine.md` |
| P05 | 真实升级案例与首批规则 | 用真实固定证据验证产品价值，形成首批经过人工批准的规则与精确支持边。 | `prompts/P05_real_rules.md` |
| P06 | CLI 产品化与可安装分发 | 让新用户能按清晰输入得到稳定且脱敏的报告，而非只能运行开发样例。 | `prompts/P06_cli_delivery.md` |
| P07 | 安全、边界和性能硬化 | 用敌意输入、独立反例与原始基准数据检验首版是否达到工程验收。 | `prompts/P07_hardening_performance.md` |
| P08 | 独立环境重演与 beta 验收 | 在明确授权的独立实验环境中，用合成数据验证实际采集和至少一条真实升级案例。 | `prompts/P08_lab_beta.md` |
| P09 | 发布审批、真实反馈与稳定版判断 | 交付可审阅的发布产物，并在明确授权后发布和用真实使用反馈决定稳定化。 | `prompts/P09_release_feedback.md` |
| P10 | 可选运行事实探测（后续版本） | 仅在首版被复用后，补充声明态与实际容器版本的差异；不开启数据库业务访问。 | `prompts/P10_optional_runtime.md` |
| P11 | 规则维护机制与上游协作 | 建立可重复的新版本审查流程，保持旧支持边可靠，而不是无限扩展范围。 | `prompts/P11_maintenance.md` |

## 三道主要决策门

P00：是否确实有可机器判断、超过 env diff 的真实缺口；不成立就停。
P05：真实规则有没有价值、能否控制误报与未知；达不到则收缩，不硬凑覆盖。
P08/P09：重演和独立用户是否认可；没有反馈不升级为“稳定/生产级”。

中间工程阶段只核对规格和实际测试，不重复讨论项目定位，也不自动追加路线。P10/P11 需要新的显式任务授权。

## 每次只给一个提示词

首轮 CODEX_START_PROMPT；随后按 roadmap 依赖发送单个 Pxx；中断用 RESUME；审查用 REVIEW。不要把所有阶段一起扔进一个会话要求“全部完成”。
